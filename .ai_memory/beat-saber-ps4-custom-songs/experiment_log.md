### Experiment 283d: 🎉 the missing-preview bug ROOT-CAUSED + FIXED + live-validated (pipeline 0.5366)
- **The user's field report:** Open Road (deploy 1) got its menu preview; the theme song (deploy 2, right after) played the STOCK StartMeUp preview — order-dependent.
- **Root cause (from the manifest + console state):** the pack/preview pass (deploy_pack_bundle → _ensure_previews_variants → build_preview_map) gates slots on the LOCAL song_metadata.json — which Step 11 wrote at the very END of the deploy. The just-deployed slot read "not custom" at preview time → no preview baked. **Every deploy baked the PREVIOUS deploy's preview, never its own** — Open Road's preview appeared because deploy 2 baked it; StartMeUp needed a third deploy. (The dirty-check, redirects, and variant deployment were all CORRECT — the bug was purely the write ORDER.) Diagnosis tools that cracked it: pack_modes_bundles/manifest.json's `previews` list (RS showed [MessItUp] while StartMeUp was the new deploy) + previewsAt unix timestamps (console mtimes lie — PS4 clock skew).
- **Fixed (pipeline 0.5366):** the target's metadata registers LOCALLY (manage_song_metadata deploy=False, idempotent) BEFORE the pack pass; Step 11 keeps the upload. Regression-pinned by test_exp283d_preview_metadata_order.py (source-order assertions).
- **Live-validated:** the theme → StartMeUp re-deploy now shows the early registration (20:49:20) BEFORE the variant build (20:49:28) which cut ✂️ BOTH MessItUp (preserved, start 30.0s) AND StartMeUp (start 4.0s) — validation PASSED; the console state REPAIRED (StartMeUp now carries its custom preview). The manifest records previews=[MessItUp, StartMeUp].
- **Also:** two old-state-pinned tests made state-dynamic (the 47-loadout-era ==9/==0.0/4-sets pins broke when the clean-slate legitimately changed the local state — now they assert the real invariants). Suite: 948 passed + 87 gated.
