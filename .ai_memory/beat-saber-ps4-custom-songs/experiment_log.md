### Experiment 252: The missing .hidden rule (permanent spinners) + panel-ID mismatch (backup crash) + feedback on Deploy/Verify/PS4 (2026-10-04)
- **Date:** 2026-10-04
- **User reports (from live use of 0.4.2):** Full Loadout + Backup/Restore show a permanent "Working…" spinner section BEFORE any action; backup click → dialog error `Couldn't start the backup: Cannot set properties of null (setting 'textContent')`; Deploy tab + Verify button give no working feedback; PS4 tab could use a spinner. ("Everywhere you have a loading spinner right now it shows at all times instead of only during work.")
- **RCA (two bugs, both mine from Exp 250):**
  1. **The generic `hidden` class had NO CSS rule.** The stylesheet only defined `.page.hidden` — every non-page element using `class="… hidden"` (all three job panels, the deploy-cancel button, the verify button, the browse panel, picked-song card, deploy log…) rendered unconditionally. The panels' `hidden` in markup was decorative.
  2. **The Backup panel's child IDs mismatched the shared panel machinery**: HTML used `backup-job-{spinner,status,label,command,log}` but showJobPanel() derives `panelId + "-status"` = `backup-job-panel-status` → `$(...)` null → `textContent` throw → the catch fired the user's dialog. Manage/Loadout panels happened to use the right convention; only Backup was wrong.
- **Fixes (webapp 0.4.3):** standalone `.hidden { display:none; }` rule (with a comment explaining the trap); Backup panel IDs aligned. **Verification hardened**: a static audit script now cross-checks EVERY JS-referenced id (incl. all panels × 5 children) against the served HTML — NONE missing; live-serve check confirms panels carry `hidden` in their class; full backup E2E re-run through the endpoint (30 lines, exit 0, zip created).
- **Added (user asks):** Deploy progress row (spinner + Deploying + song→slot label; button disables/relabels); Verify button feedback (spinner + Verifying… + progress row + live console); PS4 tab loading spinner during reads.
- **Lesson (durable):** the `.page.hidden`-only rule was a silent API: adding `hidden` to new elements "worked" in markup but did nothing — and the Pages/panel work never exercised non-page hidden elements until Exp 250 added three. A `.hidden` utility class must be global; panel child IDs must be derived, never hand-typed.
