# Experiment Log: Beat Saber PS4 Custom Song Support — M11 In-Game Plugin Toggle

**Feature:** Toggle the global plugin ON/OFF from inside the game with only a
controller — hold **L3+R3 for 2 seconds** on a DualShock 4 → the plugin flips
`enable_plugin` inside `features.json` (persist-only; a notification shows the
new state; **restart Beat Saber to apply** — user-approved). No PC required to
switch between all-custom and 100% stock. Feature flag:
`enable_in_game_plugin_toggle` (new, defaults false). Plan:
`.agent/plans/in-game-global-plugin-enable-toggle-plan.md`.
**Started:** 2026-10-14 (Exp 278)
**System:** PS4 FW 9.00, GoldHEN 2.3 / 2.4b16.2
**Archive:** Exps 268-277 (M10 Song Previews) → `experiment_log_archive/experiment_log_song-previews_exp268-277_2026-10-09_to_2026-10-14.md`

- **Research — every open question RESOLVED, verified against real bytes + two independent SDK sources:**
  - **The game reads pads via native `scePadRead`** — NOT `scePadReadState`, NOT a managed Input.GetKey hook. Proven by decoding ALL 849 NID-obfuscated dynamic imports of the decrypted eboot (new reusable script `development/scripts/ps4_elf_imports.py`: PS4 ELFs have no section headers; DT_SCE_* dynamic-tag values are offsets relative to the PT_SCE_DYNLIBDATA segment — proven self-consistent: strtab 0x18+strsz 0x3ca0==symtab 0x3cb8; symtab+symtabsz==jmprel) joined against shadPS4Plus's aerolib NID DB (94,276 entries; 846/849 decoded). Beat Saber imports scePadInit/Open/Close/Read + 10 more libScePad functions.
  - **Move-proof by construction:** Moves are read via the separate `libSceMove` (`sceMoveReadStateRecent` etc. in the imports) — `scePadRead` polls carry DS4-class pads only; a Move physically cannot set L3/R3 bits.
  - **Button bits + layout dual-verified** (OpenOrbis `orbis/_types/pad.h` + shadPS4Plus `pad.h`): L3=0x0002, R3=0x0004; `buttons` u32 at offset 0 of `OrbisPadData`; most-recent sample = `data[n-1]` of `scePadRead(handle, data, num)`.
  - **Time source:** `sceKernelGetProcessTime()` (µs monotonic, `orbis/libkernel.h` — same lib the plugin links). 2 s = 2,000,000 µs.
  - **Hook mechanism:** `dlsym(RTLD_DEFAULT, "scePadRead")` + GoldHEN Detour (the proven il2cpp_string_new pattern), lazy install from `open_hook()` with retries (libScePad loads with the game).
- **Design locked (user-approved):** clean combo (`buttons == 0x0006` EXACTLY — any other digital bit resets the hold; analog L2/R2 rest is harmless), 2 s hold, release latch, **persist-only** (flip features.json for the NEXT boot; the current session NEVER changes mid-game — eliminates every mixed-state hazard), **in-place surgical flip** of the `enable_plugin` value via memmove preserving every other key/byte (single source of truth — the pipeline's Exp-248 pull-before-push reads the LIVE file, so in-game flips flow into webapp/ps4_state/pipeline deploys automatically), **one-way-door prevention** (hotkey gated ONLY by `enable_in_game_plugin_toggle`, NOT the kill switch — a toggled-OFF user must always be able to re-enable from the couch).

### Experiment 278b (hardware result): v0.8049 L3+R3 hotkey NEVER FIRED — root cause found in the boot log (2026-10-15)
- **User:** tested on the PS4 with a regular DS4 connected to the same profile as the VR headset + Moves: the 5/5-features boot toast appeared (v0.8049 deployed ✓, flag parsed ✓), but holding L3+R3 never produced a notification. User hypothesis: the DS4 is completely disabled in Beat Saber so its inputs are ignored; requested a button combination the MOVE controller has. Also asked whether the deploy used our pipeline/webapp and whether a song was redeployed (answer: webapp API for flag+verify, pipeline CLI --deploy-plugin for the plugin; NO song redeploy — the hotkey lives in the plugin + features.json only).
- **Log analysis (archived v0.8049_hotkey_test_failure_l3r3.txt, log cleared after):** 1,491 lines, one boot session. `features: ... in_game_plugin_toggle=1` + "hotkey ARMED" logged ✓. **THE ROOT CAUSE: `dlsym(RTLD_DEFAULT, "scePadRead")` FAILED — 100 logged attempts, then "ERROR: scePadRead never found" (re-logged on every open — a give-up-flag bug). The hook never installed, so no pad data was ever observed.** Lesson (durable, now in the KB): **Sony system libraries export functions under their NIDs, not readable names** — the game imports scePadRead as NID `q1cHNfGycLI`; readable-name dlsym only ever worked in this codebase for eboot-exported symbols (il2cpp_string_new). ALL future system-library hooks must resolve BY NID.
- **Second finding (user's, confirmed):** the DS4 is ignored in VR mode — Beat Saber's input path is the Move controllers.
- **Status:** ❌ v1 hotkey dead on hardware; root cause fully understood. → Exp 278c redesign.

- **User:** tested the Move button + trigger combo (2-5 second holds, from the song list, and again from a fresh boot) — no notification, no change even after restart. Customs confirmed still working. "I feel like we're close."

Also confirmed from the module-name diagnostics: eboot.bin is module[0] from the first open; Il2CppUserAssemblies.prx (the game code) is a SEPARATE module at 0x806c0000 — the eboot carries the PLT/GOT/imports.
- **The definitive mechanism (implemented in v0.8051):** resolve via **the EBOOT'S GOT** — the eboot's JMPREL relocations (Elf64_Rela, type R_X86_64_JUMP_SLOT) name the import slots whose vaddrs hold the loader-bound FINAL function addresses. Computed from the decrypted dump's dynlib data: **sceMoveReadStateRecent → GOT RVA 0x1c634e8; scePadRead → 0x1c63500**. Plugin runtime: find `eboot.bin` by name via sceKernelGetModuleList (module[0] from the first open — log-verified) → read `*(u64*)(base+rva)` → validate mapped+readable via sceKernelQueryMemoryProtection → Detour the resolved address (hooks the library function itself — catches calls from any module). Removed the dead dlsym calls. All combo/detector/diagnostic machinery unchanged.

### Experiment 278e: v0.8051 black-screen hang RCA'd — Detour trampoline corrupted scePadRead's prologue; v0.8052 = GOT HIJACKING + release-lean logging; debug build deployed (2026-10-16)
- **User:** v0.8051 booted to a black screen and never reached the VR agreement screen (several minutes); they held the combo during the hang before force-closing. Also directed: put verbose logging behind the debug build; keep the release plugin lean/performant.
- **Log analysis (archived v0.8051_black_screen_hang.txt, 109 lines; cleared):** the GOT resolution WORKED — `eboot.bin base: 0x400000`, `scePadRead: GOT 0x2063500 -> 0x800439fe0 (prot=0x5)`, "hooked at 800439fe0" — then **zero padRead diagnostics** and the log died at open #51 (asset loading): **the Detour trampoline over scePadRead's real code corrupted its non-relocatable (RIP-relative-dense) prologue — the game's first scePadRead call after install killed the calling thread → black-screen hang.** Second discovery: the move slot held `0xeffffffe000001a0` (a lazy-binding sentinel encoding relocation index 0x1A0; file-initial slot values are the in-eboot PLT resolver stubs 0x1822480/0x18224b0) — **PS4 JUMP_SLOTs bind LAZILY on the game's first call**, so the move hook must wait for binding (the pad slot was already bound at open #1 because input init calls it that early).
- **v0.8052 implemented:** **GOT HIJACKING** — after the slot holds a canonical pointer outside the eboot's text (lazy stubs live inside it), mprotect the RELRO page RW, save the original, write the hook address into the slot (atomic aligned 8-byte write — no races), restore the page protection; the hook calls the saved original pointer directly. No trampoline, no code patching — the entire non-relocatable-prologue crash class is structurally eliminated. Guards: mprotect/query failure aborts cleanly ("no write attempted"); move retry budget 2000 opens (binds at VR init), pad 100. **Release-lean logging (user directive):** all per-call diagnostics (raw words, change logs, retry progress) behind `#ifdef VERBOSE_LOG` (DEBUG=1 build); release logs one-time events only; form detection CACHED (no hot-path syscalls). Il2CppUserAssemblies.prx verified to import NO pad/move functions (282 imports checked) — eboot slots cover all callers.
- **Verification:** both builds clean (release 105,440 B — hijack+form strings only; debug 105,504 B — full diagnostics strings); tests updated for the hijack design (28 in the toggle file: hijack pins, trampoline-ban pins, lazy-wait pins, verbose-gating pins, form-cache pins); suite **894/894**; ruff clean. **Deployed the DEBUG build** via `--deploy-plugin --debug-logging` (canonical remote name; release restore = plain `--deploy-plugin`) + strings-verified in the deployed bytes.
