# Fast Path Bug Fix Summary
# Version 0.70.2 - July 2, 2026

## Experiment Added: Experiment 76 — Fixed HEVAG Fast-Path History Corruption Bug
**Date:** 2026-07-02
**Status:** ✅ DEPLOYED and tested

### Problem Identified (Phase 6 Investigation)
During extensive testing of the HEVAG encoder, it was discovered that when processing PCM audio sections containing all-zero samples (silence), the encoder's fast-path optimization was incorrectly resetting decoder history state.

**Root Cause:**
- The fast path returned: `return _SILENCE_FRAME, 0, 0` – setting h1=0 and h2=0
- This violated the expected behavior where silence frames should preserve previous history to maintain waveform continuity
- After a non-silence frame (with established history), followed by a silence frame, the decoder state was reset to zero instead of maintaining the continuation context

### Impact Analysis
This bug affected:
- Audio transitions from silence back to active content
- Quality of generated waveforms after silent sections
- Overall fidelity of test tone sequences with intentional silence pauses

### Solution Implemented
**File Modified:** `beat_saber_deluxe/tools/hevag_encoder.py`
**Lines Changed:** Line 80 (fast path return statement)

**Before:**
```python
if all(s == 0 for s in samples):
    return _SILENCE_FRAME, 0, 0
```

**After:**
```python
# Important: keep history state unchanged so decoder's next frame starts with correct context.
if all(s == 0 for s in samples):
    # Return zero frame but preserve previous h1/h2
    return _SILENCE_FRAME, h1, h2
```
